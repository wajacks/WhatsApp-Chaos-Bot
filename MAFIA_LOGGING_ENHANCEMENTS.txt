=============================================================================
HOW TO DEBUG IDENTITY MATCHING ISSUES
=============================================================================

When a player reports night actions not working:

1. CHECK JOIN PROCESS:
   Look for: [MAFIA JOIN] logs when they joined
   Verify: Their ID was stored correctly

2. CHECK ROSTER:
   Look for: [ROSTER] logs at night phase start
   Verify: Their ID appears in the roster

3. CHECK DM RECEIPT:
   Look for: [IDENTITY] log showing Context: DM
   Verify: Their senderId is being extracted

4. CHECK NIGHT ACTION:
   Look for: [NIGHT ACTION] log showing their command
   Verify: raw_user contains correct ID

5. CHECK PLAYER LOOKUP:
   Look for: [GET PLAYER] logs during night action processing
   Verify: 
   - input_id matches what was stored
   - normalized IDs match
   - If "No match" appears, compare stored vs looking_for IDs

6. CHECK CANONICALIZATION:
   Look for: [CANONICALIZE] logs
   Verify: Same user gets same normalized ID in both contexts

=============================================================================
COMMON ID FORMATS HANDLED
=============================================================================

1. Standard WhatsApp: 254712345678@c.us
2. WhatsApp LID: some_lid_value@lid
3. Device suffix: 254712345678_12345@c.us (stripped to base)
4. Group context: message.author contains user ID
5. DM context: message.from contains user ID

All formats are normalized to consistent format for matching.
